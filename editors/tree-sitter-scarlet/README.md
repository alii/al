# tree-sitter-scarlet

Tree-sitter grammar for Scarlet. Zed builds it from this directory (see
`[grammars.scarlet]` in `editors/zed/extension.toml`); the editor queries live
in `editors/zed/languages/scarlet/`.

## Layout

- `grammar.js` — hand-written structural rules, transcribed from the reference
  parser in `crates/scarlet_syntax/src/parser`.
- `lexical.js` — **generated**, do not edit. `cargo xtask gen-editor-syntax`
  emits it (and the VSCode `scarlet.tmLanguage.json`) from the compiler's own
  token tables, so keywords, escapes, and literal shapes cannot drift from the
  scanner. `cargo test -p xtask` fails when the checked-in files are stale.
- `src/scanner.c` — external scanner for the one newline-sensitive token the
  LR grammar cannot express (a fresh-line `-` starts a new statement or match
  arm instead of continuing a subtraction).
- `src/parser.c`, `src/grammar.json`, `src/node-types.json` — generated by
  `tree-sitter generate`, checked in because grammar consumers build from
  them.

## Working on the grammar

```sh
bun install
bun run generate      # after editing grammar.js
./check-corpus.sh     # parses every .scrl in the repo; must stay clean
```

`check-corpus.sh` is the sync check against the reference parser: anything the
compiler's corpus accepts must parse here without a single error node. Run it
before committing grammar changes, and re-run `cargo xtask gen-editor-syntax`
after any token-table change in `scarlet_syntax`.
